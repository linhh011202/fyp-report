\subsection{Routing and Navigation}
\label{sec:frontend_routing}

Vue Router manages navigation throughout the application and enforces access control constraints. The routing system ensures that users can only access pages appropriate for their authentication status and role, with automatic redirection when access is denied.

\subsubsection{Navigation Guards}

Navigation guards are global checks that run before every page transition, ensuring users can only access pages they are authorised to view. Figure~\ref{fig:navigation_guard_simple} illustrates this decision process.

\begin{figure}[H]
\centering
\includegraphics[width=0.7\textwidth]{images/navigation_guard_simple.png}
\caption{Navigation Guard Decision Flow}
\label{fig:navigation_guard_simple}
\end{figure}

The guard evaluates three conditions in sequence. First, it checks whether the requested page is public (such as the sign in or sign up page). If so, access is granted immediately. Second, for protected pages, it verifies that the user is logged in; if not, the user is redirected to the sign in page. Third, for admin only pages, it checks whether the logged in user has administrator privileges; non admin users are redirected to the regular dashboard. This layered approach ensures that every navigation action is validated before the page loads.

\subsubsection{Automatic Token Management}

The frontend automatically manages authentication tokens on all API requests, ensuring seamless operation without manual intervention. Figure~\ref{fig:token_auto_refresh_simple} illustrates how this mechanism works.

\begin{figure}[H]
\centering
\includegraphics[width=0.7\textwidth]{images/token_auto_refresh_simple.png}
\caption{Frontend Automatic Token Refresh}
\label{fig:token_auto_refresh_simple}
\end{figure}

When any page makes a request to the backend, the system automatically attaches the user's authentication token. If the backend accepts the request, the data is returned normally. However, if the token has expired, the system detects the authentication error and automatically attempts to obtain a fresh token from the backend. If the refresh succeeds, the original request is retried transparently. The user never notices the interruption. If the refresh fails (for example, because the user's session was revoked), the system clears all stored credentials and redirects the user to the sign in page.

This approach provides a balance between security and user experience: tokens expire regularly for security purposes, but users are not unnecessarily interrupted unless reauthentication is truly required.
